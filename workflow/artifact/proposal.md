# Proposal Artifact

## Purpose

A proposal is the worker's handoff to the reviewer.

It explains what changed, why it changed, and how it was checked.

## Required Sections

A proposal must include:

- task
- summary
- changed files
- implementation notes
- commands run
- results
- risks
- reviewer checklist

## Changed Files

For each changed file, explain:

- what changed
- why it changed
- whether the change is generated or source

## Commands

The worker must list commands run.

For each command, include:

- command
- status
- relevant output path
- failure reason if failed

## Risks

The proposal must state known risks.

If there are no known risks, say so explicitly.

## Reviewer Checklist

The proposal should tell the reviewer what to inspect first.

## Rule

A proposal must not claim success if checks failed.

A proposal must not hide skipped checks.
